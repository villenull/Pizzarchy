## 0. Before you touch the Deck

### 0.1 The floor — what always gets you out

| Situation | Escape |
|---|---|
| Screen locked, nothing to type into | **Type the password** — STEAM+X raises the keyboard over the lock. Else **hold Power ~10 s.** ⚠️ `clear_crashed_lockscreen` is *not* this escape; see below (`docs/RECOVERY.md`) |
| No input at all — no pointer, no keys | `ssh steamdeck` → `systemctl --user restart deck-input-mapper` |
| SSH unreachable and screen unusable | **Hold Power ~10 s.** Boot leaves `lizard_mode=Y`, so the firmware supplies a pointer and arrows again |
| Will not boot at all | Volume Down + Power → boot manager → previous Limine entry, or Valve recovery (`docs/RECOVERY.md`) |

🔴 **Row 1 was WRONG as written and is corrected above.** It used to offer
`hl.clear_crashed_lockscreen()` over a bare `ssh steamdeck`. Executed
against a real lock on 2026-08-11 it failed **twice over**: over SSH `hyprctl`
has no `HYPRLAND_INSTANCE_SIGNATURE` at all, and once that is supplied the call
**refuses** — it clears a *crashed* lock screen, not a healthy one, and healthy
is what the power button produces. There is no unlock IPC. Full account and the
signature-resolving invocation: `docs/RECOVERY.md`.

⚠️ **The 10-second hold is the real floor**, because the module parameter resets
on boot by design. Nothing in this session persists `lizard_mode` independently
of the mapper — that is the whole point of the fallback.

## 1. 🔴 FIRST, and from the USB: does the live ISO have the lizard knob?

**Why first:** it is read-only, it changes nothing, and it gates whether T4 has
a product at all (§5.26). If it fails, the rest of this session still stands but
T4's design needs rework — better to know at the start.

⚠️ **This must run from the BOOTED ISO, not the installed system.** Every
lizard-mode measurement this project owns came from the installed system running
Valve's Neptune kernel; the ISO boots a different kernel entirely.

1. Deck off. Insert the Ventoy USB.
2. Hold **Volume Down**, press **Power**, release on the chime. Choose the USB,
   then the Omarchy ISO.
3. At the installer's first screen, reach a shell (the ISO's own console).
4. Run, and **write the output into `docs/PROGRESS.md` §5.26**:

```bash
ls -l /sys/module/hid_steam/parameters/lizard_mode; cat /sys/module/hid_steam/parameters/lizard_mode; uname -r
```

| Result | Meaning |
|---|---|
| File exists, prints `Y`, `uname -r` is not a Neptune kernel | ✅ The gate is open. T4's text-entry design stands |
| File missing | 🔴 **Stop and report.** T4 has no keyboard in the installer; the design needs rework before any screen is written |
| Exists but not writable | 🟡 Report the exact mode; the design may still work via `modprobe` at ISO build time |

### 2.1 The proof that matters — the fallback, on real hardware

This is the step the whole design exists for. **Do it before relying on
`lizard_mode=N` for anything else.**

```bash
ssh steamdeck 'cat /sys/module/hid_steam/parameters/lizard_mode'          # expect Y
ssh steamdeck 'systemctl --user restart deck-input-mapper'
ssh steamdeck 'cat /sys/module/hid_steam/parameters/lizard_mode'          # expect N
ssh steamdeck 'systemctl --user stop deck-input-mapper'
ssh steamdeck 'cat /sys/module/hid_steam/parameters/lizard_mode'          # expect Y  <-- the fallback
ssh steamdeck 'systemctl --user start deck-input-mapper'
```

- [ ] `Y → N → Y → N` exactly. **If the third read is not `Y`, stop** — the
      fallback is not working and every later step assumes it is.

Then the harder cases, which a clean stop does not exercise. **`systemctl kill`
defaults to SIGTERM**, which was never the broken path — SIGKILL is, because it
uses the sticky cgroup kill that also kills `ExecStopPost`:

```bash
ssh steamdeck 'systemctl --user kill --signal=SIGKILL deck-input-mapper; sleep 1; cat /sys/module/hid_steam/parameters/lizard_mode'
ssh steamdeck 'sleep 4; systemctl --user is-active deck-input-mapper; cat /sys/module/hid_steam/parameters/lizard_mode'
```

- [ ] First read is **`Y`** — `ExecStopPost` was killed, and `OnFailure=` fired
      the restore unit instead. Measured on systemd 261 at **+106 ms**.
- [ ] Second read is **`N`** with the mapper `active` — `Restart=` brought it
      back and its `ExecStartPost` re-asserted the knob.

⚠️ **The knob deliberately flaps** during an auto-restart: off → (crash) → on →
(restart) → off. The restore unit can only ever write **`on`**, the safe value,
and the measured margin is ~2 s. Losing that race would cost STEAM+X until the
next restart — **never input**.

*(All eight kill paths were verified off-hardware before this session:
`stop`, `kill` with SIGTERM, SIGKILL of the main pid, `systemctl kill -s
SIGKILL`, `--kill-whom=all`, a raw `cgroup.kill`, and both routes to the start
limit. Every one ends with the invariant intact. This step is confirming that
on the real device, not discovering it.)*

## 3. ✅ DONE 2026-08-11 — QAM is `BTN_BASE` (294)

**Measured, wired, deployed, suite green.** Startup now logs
``QAM (BTN_BASE) -> `omarchy-menu toggle` `` instead of the INERT line. The
constant is set in `src/deck-input-mapper.py`; the fact is in `docs/PROGRESS.md`
§7. STEAM is `BTN_MODE` (316) on the same node, `/dev/input/event7`.

🐞 **DO NOT USE THE PROBE BELOW — it can report a working button as dead.** It
takes `pads[-1]` on faith, and this hardware enumerates **four** nodes of which
**two are completely silent**: `event5` and `event6`, both named "Valve Software
Steam Controller", emitted nothing across a 75-second window in which every
button worked. A single-node probe that picks one of those sees nothing and
reports a dead button — R-29's exact shape. **Watch every candidate node at once
and label the source.** Also press a known-good button as a **delimiter** either
side of the button under test (§7), so a silent result is attributable: the
capture that answered this read 304, **294**, **294**, 304, 316.

*(Original text kept below for the method, not the command.)*

The QAM button's evdev code **had never been measured**. The binding shipped
inert and said so at startup, precisely so this could be filled in from one press.

```bash
ssh steamdeck 'systemctl --user start deck-input-mapper'   # lizard mode now N, so STEAM and QAM are visible
ssh -t steamdeck "sudo python3 -c \"
from evdev import InputDevice, ecodes as e, list_devices
cands = [InputDevice(p) for p in list_devices()]
pads  = [d for d in cands if e.EV_KEY in d.capabilities() and e.BTN_SOUTH in d.capabilities()[e.EV_KEY]]
if not pads:
    raise SystemExit('no gamepad node found -- is lizard_mode N and the mapper running?')
print('candidates:', [(d.path, d.name) for d in pads])
d = pads[-1]
print('watching', d.path, d.name, '-- press QAM now, Ctrl-C to stop')
for ev in d.read_loop():
    if ev.type == e.EV_KEY and ev.value == 1:
        print(ev.code, e.bytype[e.EV_KEY].get(ev.code))
\""
`````

## 4. The lock fix — and it can only be judged by looking

Two changes (§5.24). Apply, then verify by **looking at the panel**.

```bash
ssh steamdeck 'systemctl --user mask omarchy-sleep-lock.service'
```

Then add the layer rule to the Deck's Hyprland config and reload. ✅ **Which file
was a choice; it was settled on execution:** it went into
`~/.config/hypr/input.lua`, one of the five user files that are upstream's
sanctioned override seam, **not** a new `deck.lua` (§5.24 records why). That is
also where §5.20a's OSK keyboard-layout block and §5.30c's touch transform now
live, so anything writing that file must preserve the others.
**T5 must bake it into the image** — a rule that lives only in one user's
dotfile is absent from a fresh install (§5.12b: `/etc/skel` alone is too late,
the user already exists by then). The text to bake in, comment and sentinel
included, is `docs/tasks/T5-fork-plan.md` §5.6:

```
hl.layer_rule({ match = { namespace = "deck-osk" }, above_lock = 2 })
```

⚠️ **`hyprctl` over SSH needs the instance signature or it never runs at all** —
it exits with `HYPRLAND_INSTANCE_SIGNATURE not set! (is hyprland running?)` and
`configerrors` then reports nothing *because it never ran*, which reads exactly
like a pass (R-46, `docs/findings/P18-osk-hardware-pass.md`). Resolve it first:

```bash
ssh steamdeck 'export HYPRLAND_INSTANCE_SIGNATURE=$(ls -t /run/user/1000/hypr/ | head -1); hyprctl reload && hyprctl configerrors'
```

- [ ] `configerrors` reports nothing. ⚠️ This catches a **renamed key** and
      nothing else. A Lua **syntax error makes Hyprland discard the whole file**,
      and a discarded file produces no config errors *because none of it was
      parsed* — so this checkbox is green in exactly the case you care about.

🔴 **The check that can actually fail.** End the file with a sentinel and
**assert** it — `hyprctl eval` never reports a value, so a readback is worthless
(see below). Append as the last statement of `~/.config/hypr/input.lua`:

```lua
DECK_INPUT_LUA_LOADED = true
```

then, after the reload above:

```bash
ssh steamdeck 'export HYPRLAND_INSTANCE_SIGNATURE=$(ls -t /run/user/1000/hypr/ | head -1); hyprctl eval "if DECK_INPUT_LUA_LOADED == nil then error(\"input.lua was discarded\") end"'
```

- [ ] It exits **0** and prints `ok`. **Exit 7** with the message means the file
      was discarded and the layer rule below is not in effect.

⚠️ **Do not "simplify" that into reading the sentinel back.** Measured on this
Deck 2026-08-12 (Hyprland 0.56.2): `hyprctl eval` prints `ok` — its own status,
never the expression's value — and exits **0** for anything that does not raise,
including a global that has never existed. Only a Lua `error()` surfaces, as
exit 7. A readback is a checkbox that cannot fail, and one was ticked on that
basis (`docs/PROGRESS.md` §5.30c). `test/unit/test-hyprctl-syntax.sh` scanner 3
now fails CI if the readback form reappears in the repo.
